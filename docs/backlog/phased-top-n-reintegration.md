# Backlog: вернуть «Поэтапный Top-N»

**Статус:** отложено.

«Поэтапный Top-N» временно скрыт из пользовательского интерфейса. Текущий
Control API сохраняет конфигурацию стратегии, но не запускает подтверждённый
многоэтапный алгоритм с независимой финальной проверкой. Нельзя предлагать
пользователю метод, результат которого продукт пока не умеет выполнить и
обосновать измерениями.

## Условия возврата в интерфейс

Вернуть карточку метода и фильтр можно только после выполнения всех условий:

1. Целевой runtime действительно выполняет ограниченные этапы поиска, сохраняет
   Top-N победителей каждого этапа и проводит независимую финальную проверку.
2. Контракт фиксирует порядок этапов, лимиты кандидатов, правила передачи
   победителей и состав артефактов с доказательствами измерений.
3. Есть интеграционный тест с реальными ClickHouse source и sandbox, который
   подтверждает эти этапы, корректную обработку ошибок и очистку ресурсов.
4. Отдельно принято решение о миграции существующих сохранённых стратегий с
   `procedure: phased`; интерфейс не должен менять их поведение неявно.
5. Тексты интерфейса объясняют, чем этот метод отличается от
   «Последовательного Top-N», без неподтверждённых обещаний.

## До возврата

- Поддерживать чтение уже сохранённых конфигураций со значением `phased`.
- Не показывать «Поэтапный Top-N» при создании, редактировании и фильтрации
  стратегий.
- Не удалять значение из версионированного API-контракта без отдельного решения
  о миграции данных.
